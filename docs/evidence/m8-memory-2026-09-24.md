## The scenario

One project, `kiosk`, whose repository is a tiny static site: `index.html` and `about.html` link to `/buy` and include `css/site.css`, `contact.html` does neither, and there are two checkout pages, `checkout-classic.html` and `checkout-express.html`, with nothing saying which is "our checkout page".
Everything is driven as the captain drives it: lines typed into the Mate's pane with `send.Send`, console gestures through `consoleAction`, the observer (with the timeline) and the outbox sender started as `cmdConsole` starts them, manual mode.
When a Crew's hand-back or question sits in the inbox and the Mate has not acted on it, the captain presses `[assign]` once.

1. The captain asks for a scout: which pages link to `/buy`.
   After it hands back and the Mate relays the findings, the captain gives one standing rule: "whenever a crew's report mentions a file, it must cite it as path:line with the line number, and a crew must never commit report or note files to the repository".
   Asserted: a `memory.md` `## Lessons` entry that `memory check`'s parser accepts, or a proposal for `CREW.md`; nothing in Claude's auto-memory directory for the Mate's cwd or in the lab `CODEX_HOME`'s `memories/`.
2. The captain closes the scout and asks for a "Buy now" button linking to "our checkout page".
   The Mate escalates the choice; before answering, the captain presses Restart in the console.
   Asserted: the outcome opens with `stowed`, and afterwards `backlog.md` `## Held for the captain` holds the question with today's date, verbatim from one of the Mate's messages to the captain.
3. For the `-fresh` variants the Mate is then stopped without a stow and started with `Fresh`, so only the files carry anything over.
   Asserted: asked "What are you waiting on?", the Mate names the checkout question; asked for a second scout (which pages include `css/site.css`), the brief's `## Build` carries the rule; after the second Crew's spawn the Mate sends it no line repeating the rule, in `sent.log` and in the timeline's `message` table.
4. `memory check` passes, and `recall` carries the lesson and the held line.

## Product changes found by this acceptance

- **F1: the Mate's environment on every launch.**
  Herdr's `tab create` does not inherit the workspace's `--env` (measured in a probe lab: the workspace was created with `--env FOO_T=ws`, and a tab created without `--env` echoed `FOO_T` empty).
  A Mate restarted while a Crew holds its workspace is exactly such a tab, so it lost `MATEV2_AGENT_ROLE`, `MATEV2_CALLER` and the rest of its identity, and its sends would have been recorded as the captain's.
  `Herdr.StartAgent` now exports the launch's environment into the pane before every start, beside the existing `unset`, and the Mate's launch carries its identity and `CODEX_HOME`.
  Every restart in step 2 had the ship Crew alive, so every pass above exercised this path.
- **F2: restart keeps the harness.**
  `restart_mate` started the workspace default, so a Codex Mate came back as a fresh Claude Mate; it now reads the harness from `mate.meta`.
- **F3: a Codex stow ends on the rollout, not on the composer.**
  A Codex composer reads empty between tool calls, so "busy, then empty twice" declared the stow over while the Mate was still filing, and the restart interrupted it.
  With `mate.meta` naming the rollout, the stow now ends only on a `task_complete` stamped after the stow line (`harness.CodexTurnCompletedAfter`); the composer rule is kept only for a Codex Mate whose rollout is not yet known.
- The console's workspace root for `MATEV2_LIVE_KEEP` refused subtest names (the `/`), fixed in `liveWorkspaceRoot`.
